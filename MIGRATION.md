> [!IMPORTANT]
> **Order of Operations for Backfill:**
> Before running `python -m saltmdb --backfill-chunk-embeddings`, the `entity_embeddings` virtual `vec0` table **must** be created. 
> 
> You can create it by either:
> 1. Launching the server once (`python -m saltmdb`), or
> 2. Running `python -c "from saltmdb.db.schema import init_db; init_db()"`
> 
> If `python -m saltmdb --backfill-chunk-embeddings` is executed before initializing `init_db()`, embedding generation will fail with `no such table: entity_embeddings` and mark entity statuses as `failed`. If this happens, run `init_db()`, reset failed records (`UPDATE entities SET embedding_status = 'pending' WHERE embedding_status = 'failed'`), and re-run `python -m saltmdb --backfill-chunk-embeddings`.

```bash
python -m saltmdb --backfill-chunk-embeddings
```

## DDL Migrations (v0.1.0-alpha.84 ➔ v0.1.0-alpha.85)

Alpha.85 replaces the unused host-provided event session pointer with a UUIDv7 minted by each
MCP adapter process. The event column is renamed to `agent_session_id`; entities additionally
record both the creating session and the most recent writing session. `init_db()` applies these
changes idempotently, but production operators performing a manual upgrade should take a verified
backup first and run:

```sql
-- Rename the never-populated event correlation column and rebuild its index.
DROP INDEX IF EXISTS idx_events_session;
ALTER TABLE events DROP COLUMN session_id;
ALTER TABLE events ADD COLUMN agent_session_id TEXT;
CREATE INDEX IF NOT EXISTS idx_events_agent_session
    ON events(agent_session_id, timestamp DESC);

-- Preserve entity creation provenance separately from the last writer.
ALTER TABLE entities ADD COLUMN agent_session_id TEXT;
ALTER TABLE entities ADD COLUMN last_touched_session_id TEXT;
CREATE INDEX IF NOT EXISTS idx_entities_agent_session
    ON entities(agent_session_id, created_at DESC)
    WHERE status != 'archived';
```

Existing rows remain NULL because no real host session identifier was previously stored. New
writes populate both entity columns on creation; targeted updates change only
`last_touched_session_id`.
