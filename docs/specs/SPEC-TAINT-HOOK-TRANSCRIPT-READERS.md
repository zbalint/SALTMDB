## 1. Why

`transcript_path` arrives in the hook's stdin JSON, which model text can influence, and the common readers open it unchecked. Decision: one choke point that validates and reads in the same function (a boolean guard in another function did not satisfy the taint engine in the S5144 case, so check and open stay together), deny when undecidable, with a visible trace when it denies (a wrongly configured root would otherwise silently disable every hook). Rejected: `session_id` lookup (also tainted, and Codex file names carry timestamps); an extra SALTMDB-specific "additional roots" env var (a generic bypass with no harness behind it); `Path.is_relative_to` (the engine may not model it).

## 2. Decisions

- D1. New `read_transcript(raw: object) -> str | None` in `_saltmdb_hook_common.py` is the only function that opens a path taken from hook input. `None` or `""` means "no transcript supplied": return `None` SILENTLY (Copilot sends no `transcript_path`, and the search gate passes `""` on every call). For any other input it returns the file text or `None` when the input is not allowed or unreadable. Steps, in this order, ALL INLINE in this one function except the raw string pre-check (D5): reject non-`str`, not absolute (`os.path.isabs`), or containing a control character (`ord(c) < 0x20 or ord(c) == 0x7F`; non-ASCII characters stay allowed); `real = os.path.realpath(raw)`; for each allowed root (D2), `root_real = os.path.realpath(root)` and accept when `os.path.commonpath([os.path.normcase(root_real), os.path.normcase(real)]) == os.path.normcase(root_real)` (catch `ValueError`, raised on mixed drives, as "not inside"); `fd = os.open(real, os.O_RDONLY | getattr(os, "O_NOFOLLOW", 0) | getattr(os, "O_NONBLOCK", 0) | getattr(os, "O_BINARY", 0))` (`O_NONBLOCK` makes a FIFO open return at once so `fstat` can reject it; `O_BINARY` stops Windows text-mode translation and Ctrl-Z EOF); in a `try/finally` that closes the fd if anything fails before `os.fdopen`, `os.fstat(fd)` must be a regular file (`stat.S_ISREG`) and `st_size` at most `_TRANSCRIPT_MAX_BYTES` (read from the module global at CALL time, not a default argument); then `with os.fdopen(fd, "rb") as handle: data = handle.read(_TRANSCRIPT_MAX_BYTES + 1)` and deny when `len(data) > _TRANSCRIPT_MAX_BYTES` (a live transcript can grow after `fstat`); decode `data.decode("utf-8", errors="replace")` (deliberate: JSONL is UTF-8, `read_text` used the locale encoding; CRLF stays `\r\n`, which `splitlines()` handles). Any `OSError`/`ValueError` gives `None`. A denial or failure of a NON-EMPTY input writes ONE line to stderr, `saltmdb hook: transcript path denied or unreadable`, without the path, at most ONCE per process (a module-level flag; the critique gate calls up to five readers per invocation). Add a `# shortcut:` comment: a parent directory can still be swapped between the `commonpath` check and the `open` by a process with write access inside the owner's home (same uid); upgrade trigger: a multi-user or shared-home deployment, then re-check `os.path.realpath(f"/proc/self/fd/{fd}")` after the open.
- D2. Allowed roots: a module function `_transcript_roots()` returning the tuple of `Path` roots, all derived from the hook process's own environment, never from hook input: Claude `$CLAUDE_CONFIG_DIR/projects` if that env var is set, else `~/.claude/projects`; Codex `$CODEX_HOME/sessions` if set, else `~/.codex/sessions`; Copilot CLI `~/.copilot/session-state`; OMP `~/.omp/agent/sessions`. `~` is `Path.home()` (so `HOME`/`USERPROFILE` isolates tests); a `RuntimeError` from `Path.home()` denies that root. An env var counts as set only when it is non-empty AND an absolute path; an empty or relative value is ignored and the home default is used (an empty value would otherwise allow `<cwd>/projects`). No other env var, no extra-roots variable. Gemini/Antigravity transcripts are protobuf and have no transcript root: always denied (same as today's empty-path behaviour). On Windows compare with `os.path.normcase` applied to both sides of the `commonpath` call. Roots are resolved with `os.path.realpath` at use time (a dotfile-managed symlinked `~/.claude` must still match).
- D3. Size cap: 256 MiB (a module constant, `_TRANSCRIPT_MAX_BYTES = 256 * 1024 * 1024`), because the largest local transcripts are 50 MB and a small cap would silently disable the search gate on long sessions. Larger files are denied with the trace of D1.
- D4. The four readers keep their signatures and their "unreadable gives empty/None" behaviour and call `read_transcript` once each: `read_transcript_full` returns `text or ""`; `read_transcript_tail` returns the last `max_lines` joined lines or `""`; `read_transcript_from_line` returns the slice or `""`; `find_last_line_matching` returns the last 1-indexed matching line or `None`. Their `Path(...).is_file()` pre-checks are removed (the choke point does them). No caller changes in this slice.
- D5. Complexity and literals: keep each function at or below cognitive complexity 15 (the consultant estimates the inline `read_transcript` at 10-13; the developer measures with complexipy from a scratch venv and reports) and never repeat a string literal three times (the trace text is one constant). `realpath`, `commonpath`, the `open` and the read STAY INLINE in `read_transcript` (a boolean guard in a helper did not satisfy the engine in the S5144 case). Only two helpers may be split out, neither of which opens or sanitizes anything: `_raw_path_ok(raw) -> str | None` (the string pre-checks, returning the string or `None`) and `_transcript_roots() -> tuple[Path, ...]`. If the engine still flags after this slice, the architect decides the next shape (section 7).
- D6. Fallback shape, pre-agreed but NOT built in this slice: if Sonar still flags lines after this slice, slice 1b lists the validated parent directory with `os.scandir` and opens the entry whose name equals the requested basename. The developer does not build it.

- Existing-target discipline (otherwise the mutant is masked by ENOENT): the `../` escape target, the symlink-inside-pointing-outside target and the outside-root file all EXIST as regular files (`<home>/secret.jsonl`, `<home>/other/x.jsonl`). Relative-path test: `monkeypatch.chdir(<root>/<slug>)` and pass `"s.jsonl"`, which exists there. Control-character test: a file whose name contains a newline INSIDE the root (legal on Linux) is denied (a NUL is rejected by `os.open` itself and proves nothing). FIFO test: assert `read_transcript(fifo) is None` directly (not through `read_transcript_full`, whose `""` hides the difference), run in a thread with `join(timeout)` and fail if the thread is still alive (a dropped `O_NONBLOCK` hangs instead of failing). Size-cap test also patches `os.fstat` to report a small size over a larger file and asserts denial (live growth), and pins that the cap is read at call time.
- Empty and `None` input return `None` with NO stderr output; a non-empty denied input prints the trace line exactly ONCE over two denied reader calls in one process (reset the module flag in the test setup); the line does not contain the path.
- Env roots: `CLAUDE_CONFIG_DIR=""` and `CLAUDE_CONFIG_DIR="relative/dir"` fall back to `~/.claude/projects` and do not open `<cwd>/projects/x.jsonl` (chdir to a tmp dir containing it); unlisted `XDG_DATA_HOME` and `COPILOT_HOME` pointing at a tmp dir with a valid-looking file are denied. Tests clear `CLAUDE_CONFIG_DIR` and `CODEX_HOME` unless they set them.
- Optional on Linux: the count of `/proc/self/fd` entries is unchanged after 50 denials (no fd leak).
- Mutants that may legitimately survive on Linux CI and are NOT to be chased: dropping `O_NOFOLLOW`, `O_BINARY`, `normcase`.
- Prefix confusion: `<home>/.claude/projects-evil/x.jsonl` and `<home>/.claude/projectsX/x.jsonl` are denied (a `startswith` mutant survives otherwise).
- Reader semantics unchanged on an allowed file: `read_transcript_full`, `_tail` (with `max_lines` smaller than the file), `_from_line` (including `start_line` 0 and a large value), `find_last_line_matching` (last of several, none, substring not regex). One denial test per reader (each returns its empty value on a path outside the roots).
- No path value ever reaches the stderr line or the return value of a denied call.
- Existing `hooks/tests` stay green with only the setup isolation.
