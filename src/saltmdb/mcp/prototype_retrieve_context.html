    Findings this prototype surfaced (read before locking Milestone A's spec)
    

      
    
        
  1. Drop sol:high's separate top-level primary array. G6 already said every
          memory must explain its own inclusion via retrieval_provenance — that fully
          subsumes a parallel primary list. One memories[] array, each item
          tagged inclusion: "primary" | "expansion" | "conflict_only", is sufficient and
          removes a redundant field nobody had actually decided how to keep in sync.
    2. 
        
  2. Real naming collision between G4 and G8, both named expansion_truncated.
          G4's is a fan-out/node-eligibility signal; G8's is a token-budget/payload-size signal — the map
          itself says these are independent axes, but both were given the identical flat field name in
          two different resolution write-ups. Flattened, they'd silently shadow each other. Fix applied
          here: namespace them as metadata.fan_out.expansion_truncated vs.
          metadata.budget.expansion_truncated — toggle both free-play buttons independently
          below to see they really are orthogonal once namespaced.
    3. 
        
  3. G7's "extends G4's expansion_truncated signal" reading, applied literally:
          conflict-set-cap truncation is reported at metadata.fan_out.conflict_sets_truncated
          (same family as the general fan-out cap), not a third independent truncation flag.
    4. 
        
  4. Resolved conflicts fully vacate conflict_sets. Read literally, G7 says a
          lifecycle-resolved conflict surfaces "via the ordinary lineage path, NOT the conflict reserve" —
          taken at face value, that means it doesn't appear in conflict_sets at all once
          resolved, only in lineage. That has a real cost: the fact that two memories were
          ever explicitly flagged contradicts (not just superseded) disappears from the
          response. This is exactly the open gap in memory 8cd3413f. Proposed
          (NOT locked by any ticket — flag for explicit sign-off): a single
          lineage[head].was_flagged_contradiction: true boolean, which preserves the signal
          without reintroducing a members/edges structure into the lineage path. See the contradiction
          walkthrough, step 2.
    5. 
        
  5. No locked cap on lineage historical length. The real map's own supersession
          chain (memory e567fdf8) is 10 revisions deep as of this session — the
          lifecycle scenario below is not a contrived depth, it's what get_lineage returns
          today. Neither G7 nor G8 locked a truncation rule for the lineage path the way they
          did for the primary/expansion budget pass and the conflict reserve. This needs its own decision
          before Milestone A locks (does a 10-deep chain get capped? by whose budget?) — currently fog.
