- D2 The coupling test `tests/test_surface_coupling.py` scans text files and fails with file, line and reason on: (a) any `mcp__saltmdb__<name>` where `<name>` (`[A-Za-z_]+`) is not a registered tool; a following `*` marks a glob and is not checked; (b) any call-shaped mention whose arguments name a field that is not a property of that tool's schema, or is in `REMOVED_FIELDS`/`RENAMED_FIELDS` for it. Call-shaped = a registered or removed tool name not preceded by a word character or a dot and immediately followed by `(`, searched in the WHOLE text of every scanned file (inline code spans wrap across lines, and hook prompts are Python string literals with no backticks). Arguments are collected up to the matching `)` or the end of the line, whichever comes first (deliberately line-based; an argument list wrapped onto the next line is a documented false negative). Only depth-1 arguments count: anything inside `[]`, `{}` or a quoted string is skipped (so `relations=[{source_id, ...}]` and `content="a=b"` are not flagged); an argument is a `name=` token or a `"name":` token at depth 1. Documented false negatives: bare-name signatures without `=`, prose of the form "call X with field=Y", wrapped argument lists, removed tokens without backticks, qualified service calls such as `memory_service.search_memory` (skipped on purpose), and the Copilot-style names `saltmdb-<tool>`; (c) any backticked removed token (`inspect_memory`, `include_inspect`, `old_id`, `new_id`, `total_dependencies_found`, `total_related_found`, `query_keywords`); (d) any `mcp_tool` hook entry in a settings example whose `tool` is not registered or whose `input` keys are not in the schema. `capture_trace_start`, `capture_trace_memory_link` and `capture_trace_complete` are registered tools today (hook-only, BL-078), so the checks pass for them without a special case; when BL-078 removes them it must remove the examples in the same slice. The scanner is split into small parts (file iteration, tool-name finder, a tokenizer for the argument text and a collector over its tokens, backtick-token detection, the settings-JSON check, the allow-list matcher) so no function passes complexipy 12. A bare `entity_id` is NOT banned: it is a database column and a daemon RPC argument (R9) and legitimately appears in architecture prose and in the Copilot trace hook; only call-shaped and backticked PUBLIC uses are checked.

Found at the tester pass of the implementation (tester finding D4, architect review of `scripts/surface_scan.py`).

- A2.1 D1, rule (c) token list: the list is the explicit `RESPONSE_RENAMED_TOKENS` table in `scripts/surface_scan.py`, not `RENAMED_FIELDS` keys. Reason: `entity_id` and `offset` legitimately appear in backticks in the architecture and hook documents (database column, daemon RPC argument, the cursor string `offset:N`, parent R9), so the derived list would need a long allow-list that hides real drift. D2(b) keeps the union with `RENAMED_FIELDS`/`REMOVED_FIELDS` as a defensive check (a future schema that re-adds an old name still fails), which is pinned by a test with a synthetic vocabulary.
- A2.2 D4, the CLI exclusion rule: the exclusion of `src`, `tests`, `scripts` and the `docs/specs`, `hooks/tests` pairs is applied to the path RELATIVE to the root that was given on the command line (the file's own name for a file argument), never to the absolute path. The absolute-path form silently skips every file when the scanned tree lives under a directory that happens to be called `src`, `tests` or `scripts` (for example the owner's live hook sources), and reports a clean result. A test scans a fixture tree placed under `<tmp>/src/...` and `<tmp>/scripts/...` and finds a stale call in it; another test shows that a `tests` directory INSIDE the given root is still excluded.
- A2.3 D8 additions to the MIGRATION behaviour list: `get_memory` defaults to `detail="full"` (a forgotten argument never returns a snippet); the compact `search_memory` snippet is about 200 characters; whether Claude Code fires `PostToolUseFailure` instead of `PostToolUse` for an `INTERNAL_ERROR` rejection (`isError`) is unverified, and hooks registered only on `PostToolUse` would not see failures; `retrieve_context` is not a new tool (it is listed under the parameter and shape maps, not as new).
- A2.4 Tester coverage gaps the developer closes with tests: allow-list context keying (an allowed pair must not silence another use of the token in the same file), allow-list path-suffix keying (a scan from another working directory), the stale-entry check through `scan_paths` (the CLI route), depth-1 argument rules (single and double quoted keys, `[]`/`{}` nesting, identifier guard), the dot-preceded (qualified) name boundary, the nudge hook's dict preference and raw-string `tool_response` paths.
